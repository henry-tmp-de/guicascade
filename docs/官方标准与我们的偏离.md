# 我们用了官方标准的哪些部分、偏离了哪些

> 写于 2026-09-26。**这份文档是为了防止以后（包括我自己）把我们的结果
> 误当成"官方基准分数"。**

## 一句话

**任务、判分、前置状态、快照、步数预算、动作空间 —— 全部是官方原版。
设备访问层曾经是我们自己造的，2026-09-26 已换回官方。**

## 逐项对照

| 环节 | 用的是什么 | 是不是官方 |
|---|---|---|
| 任务定义、指令 | `registry.TaskRegistry.ANDROID_FAMILY` | ✅ 官方原版 |
| **判分** `is_successful()` | 官方代码，一行没改 | ✅ 官方原版 |
| **前置状态** `initialize_task()` | 官方代码，一行没改 | ✅ 官方原版 |
| 快照机制 | 官方 `utils/app_snapshot.py` | ✅ 官方原版 |
| 步数预算 | `int(10 × task.complexity)` | ✅ 官方算法 |
| 动作空间 | 照官方 `env/json_action.py` 做，两边一致 | ✅ 基本一致¹ |
| **设备访问（读界面 / 点屏幕）** | `android_env` + `-grpc`（2026-09-26 换回） | ✅ 官方 |
| Agent 主循环 | 我们自己的 | ❌ 自造（研究内容） |
| **三形态级联 / 监控器 / 路由器** | 我们自己的 | ❌ 自造（**研究内容**） |
| 前端、驱动脚本 | 我们自己的 | ❌ 自造（工具） |

¹ 官方比我们多 `status` 和 `unknown` 两个动作，我们没用。

## 曾经偏离过什么：自造的 `aw_bridge`

2026-09-25 之前，架构是：

```
Agent -> TaskEval(官方) -> 【我们的 aw_bridge】 -> adb -> 模拟器
```

`aw_bridge.py` 是我们自己写的"把官方 ADB 请求翻译成 adb 命令"的层，540 行。
**2026-09-25 一天之内从它身上查出四个 bug，每一个的症状都长成"模型不行"：**

| bug | 症状（看起来像什么） |
|---|---|
| `start_activity` 读的是 `a.activity`，而 proto 字段叫 `full_activity` | 所有 app 启动失败 -> 任务在起点就废 |
| `BoundingBox` 的 `x_max` 填成了**宽度**而不是绝对坐标 | 依赖 bbox 的判分全错 |
| `configs/apps.yaml` 漏了 17 个官方 app | `open_app` 名字查不到 -> 模型"打转" |
| 调试浮层（`pointer_location`/`show_touches`）没人关 | 屏幕被污染 |

另外还有几个不在桥接层、但也属于"我们自己造的东西"的 bug：
`render_episode` 不把动作结果告诉模型、前端写死 12 步、记录不存 `run_id`
导致历史截图全裂、`check_network` 用 ping 判断（而 QEMU 用户态网络本来就不支持 ICMP）。

## 为什么换回官方是对的

官方那套（`android_env` + gRPC accessibility forwarder）是**和 TaskEval 一起
测过的**，它不需要我们重新实现一遍"怎么跟手机说话"。

实测确认（2026-09-26）：

- `android_env` 已安装，模拟器 `-grpc 8554` 端口通
- `env_launcher.load_and_setup_env(...)` 一次连上
- `get_state()` 连续取 10 次，10/10 成功，每次 16 个元素
- `OsmAndMarker` 在官方环境下 `initialize_task` / `is_successful` / `tear_down` 全通
  —— 而它在自造桥接层下连起点都过不去

## 换掉之后，哪些东西跟着作废

| 文件 | 处置 |
|---|---|
| `scripts/aw_bridge.py` | 删 |
| `configs/apps.yaml`、`configs/apps_aw.yaml`、`scripts/gen_apps.py` | 删（官方 `open_app` 用它自己的 `_PATTERN_TO_ACTIVITY` 表） |
| `src/guicascade/envs/android.py` | 退役（被 `envs/android_official.py` 替代） |

**保留下来的**：`aw_snapshot_keep.sh`（模拟器重启后恢复快照，和用谁无关）、
`_sqlite_fts.py`（判分仍跑在我们的 Python 里，Anaconda 缺 FTS3/4 的问题还在）。

## 结果能不能和官方榜单比

**判分口径是一致的**（同一个 `is_successful`、同一个步数预算），所以
"某任务我们判成功/失败"和官方是同一个意思。

**但成功率不能直接对比**，因为做题的 Agent 不一样：官方用 M3A / SeeAct，
我们用的是自己的（2B / 8B / 级联）。**这是研究设计的一部分，不是缺陷** ——
级联研究要的就是"同一个任务、不同模型配置"的对照。

**报告里必须写清楚**：数字是"我们的 Agent 在官方任务与官方判分下的结果"，
不是"AndroidWorld 榜单成绩"。
